# Repository instructions

This repository owns toyo-cli, an independent diagnostics runtime and CLI for Toyota vehicles.

## Boundaries

- `./toyo` is the public CLI. Go code lives in `cmd/toyo/` and `internal/`; the Python package under `toyota_diag/` is the internal live transport/session runtime reached through `python -m toyota_diag`. Do not add a second public CLI.
- The SQLite runtime catalog is generated by `ghidra_rh850_analysis` (`tools/gts bundle sqlite`) from the canonical v4 bundle and lives under ignored `build/`. Clean compatibility metadata under `toyota_diag/data/` is generated data. Do not hand-edit generated Toyota metadata here.
- Do not add Toyota DLL/DDB/EXE binaries or other proprietary source artifacts. This repository consumes clean derived metadata only.
- Keep openpilot-specific integration optional. Offline catalog/search/decode functionality must not require an openpilot checkout. Direct live Panda access may use the `live` extra; managed `pandad` reuse is allowed only through lazy imports.

## Development

- Workstations: Go is sufficient for offline development. Run `uv sync --extra live` only when exercising the Python live runtime with direct Panda access.
- Comma/AGNOS: do not build a second diagnostics virtualenv. The Python bridge reuses `/usr/local/venv` and `/data/openpilot`.
- Run `go test ./...` and `uv run pytest`; build with `go build -o build/toyo ./cmd/toyo`. The Go bridge must not duplicate Panda safety/ownership behavior.
- Prefer the smallest targeted test while iterating, then run the full suite before committing changes that affect shared runtime behavior.

## Provenance

The initial standalone source was extracted from `kaikozlov/kai-openpilot` branch `kai` at commit `7cde0135351f298b9a9d84344b5f685fde5a6005` on 2026-09-12. Subsequent development belongs here rather than in an openpilot branch unless it is genuinely openpilot integration glue.
